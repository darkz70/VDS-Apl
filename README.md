# VDS-Apl — официальный Telegram-бот заявок

Бот набора в команду проектов **VoidSMP** и **Майнкилд**. Работает на Python
(`pyTelegramBotAPI`, long polling) и готов к запуску на **bothost.ru**.

## Что умеет

| Кнопка | Что происходит |
| --- | --- |
| 🎬 **Контент мейкер** | отдельный шаг выбора проектов: **VoidSMP** и **Майнкилд** — каждый отмечается своей кнопкой, можно выбрать оба |
| 🛠 **Хелпер** | сразу открывается анкета хелпера |
| 📚 **Редактор Вики (Fandom)** | сразу открывается анкета редактора вики |

Дальше бот задаёт 6 вопросов по выбранному направлению, показывает заполненную
анкету для проверки и после нажатия «Отправить» рассылает заявку
**только двум администраторам**:

- `5992994003`
- `1787475400`

Ни в группы, ни кому-либо ещё заявки не уходят. Администраторы видят карточку
с кнопками **✅ Принять**, **❌ Отклонить**, **💬 Написать заявителю**.
Решение (одобрение/отказ с причиной) бот автоматически отправляет заявителю
в личку, а карточки у обоих админов обновляются и лишаются кнопок.

Дополнительно: `/start`, `/my` (статус своих заявок), `/help`, `/about`,
`/cancel`, `/id`, `/apps` (список последних заявок, только админам).
Пока заявка висит на рассмотрении, подать вторую нельзя.

## Структура

```
bot.py            — точка входа, вся логика и обработчики
config.py         — токен, ID админов, роли, вопросы анкет, проекты, тексты
storage.py        — потокобезопасное JSON-хранилище заявок (без БД)
requirements.txt  — зависимости для Bothost
bothost.json      — подсказка хостингу: bot.py + Python 3.12
.env.example      — пример переменных для локального запуска
BOTFATHER.md      — готовые тексты для оформления бота в @BotFather
tests/            — тесты полного сценария на фейковом Telegram API
```

## Локальный запуск

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # впишите настоящий BOT_TOKEN
python bot.py
```

Токен можно не класть в `.env`, а передать переменной окружения:
`BOT_TOKEN=... python bot.py`. `.env` в Git не коммитится (см. `.gitignore`).

## Деплой на bothost.ru

1. Залейте этот репозиторий/ветку на GitHub. Сейчас код лежит в ветке
   `arena/dc0b2cd9-vds-apl` — укажите её в настройках Bothost или смержите
   изменения в `main` через pull request, если панель тянет только `main`.
2. В панели Bothost создайте бота: платформа **Telegram**, язык **Python**,
   загрузка из Git (или ZIP с файлами из корня репозитория).
   Главный файл — `bot.py`, зависимости из `requirements.txt` в корне
   (`bothost.json` уже подсказывает `main: bot.py`, Python 3.12; если в панели
   доступна только 3.10/3.11 — просто поменяйте `python_version`, код работает
   на Python 3.10+).
3. **Домен, порт и webhook боту не нужны**: используется long polling, бот сам
   опрашивает Telegram. Если в панели есть переключатель «Использовать домен» /
   «Webhook» — оставьте его выключенным. Если вебхук всё же был задан раньше,
   бот снимет его при старте (`delete_webhook`), иначе `getUpdates` упадёт с
   конфликтом. Команда запуска: `python bot.py`.
4. В разделе **Переменные окружения** задайте:
   - `BOT_TOKEN` — токен от @BotFather (на некоторых тарифах Bothost
     подставляет его автоматически; если переменная уже есть — просто проверьте);
   - `ADMIN_IDS` — можно не задавать, по умолчанию уже стоят `5992994003,1787475400`;
   - `DATA_DIR=/app/data` — если подключено постоянное хранилище, чтобы
     `applications.json` не терялся при пересборке контейнера;
   - при желании `BOT_TIMEZONE=Europe/Moscow`, `COMMUNITY_NAME=...`.
5. Запустите бота, напишите ему `/start`, затем `/id` — команда покажет ваш
   Telegram ID (полезно сверить с ID администраторов). Пройдите тестовую заявку:
   карточка должна прийти **обоим** админам и никому больше.
6. Оформите имя, описание и список команд по [BOTFATHER.md](BOTFATHER.md).

> ⚠️ Храните токен только в переменных окружения. Не коммитьте `.env` и
> `applications.json` в публичный репозиторий.

## Как поменять анкету

Всё в `config.py`:

- `ROLES[...]["questions"]` — списки вопросов по направлениям;
- `PROJECTS` — названия проектов для контент-мейкера (сейчас VoidSMP и Майнкилд);
- `ADMIN_IDS` — получатели заявок (по умолчанию два указанных ID, можно
  переопределить через переменную `ADMIN_IDS`);
- `MAX_ANSWER_LEN` — лимит длины одного ответа;
- приветственные тексты и подписи кнопок — в `bot.py`.

После изменения кода перезапустите бота в панели Bothost.

## Частые проблемы

| Симптом | Причина и решение |
| --- | --- |
| В логах `Не задан BOT_TOKEN` | Не заполнена переменная в панели Bothost |
| `Conflict: terminated by other getUpdates request` | Запущены два экземпляра с одним токеном (например, локально и на хостинге). Оставьте один |
| Бот молчит на кнопки | Нажмите `/start` заново: старое меню считается устаревшим после перезапуска |
| Заявки пропадают после редеплоя | Файловая система временная — задайте `DATA_DIR=/app/data` и подключите постоянный том |
| Админ не получил заявку | Он ни разу не писал боту `/start` или заблокировал бота. Telegram не даёт писать первым — пусть откроет чат с ботом |

